# สรุปผลงานวิจัยและบันทึกอัตโนมัติ

- GET `index.php?page=get-research-summary` อ่านอาจารย์จาก `faculty` และผลงานจาก `faculty_research` ไม่มีข้อมูลตัวอย่างสำรอง
- POST `index.php?page=save-research-summary` รับ JSON เพิ่ม/ลดรายการหนึ่งรายการต่อคำขอ และบันทึก audit ใน transaction เดียวกัน
- การกด + สร้างบันทึกจำนวนผลงานหนึ่งรายการ ใช้ 1 มกราคมสำหรับปีปฏิทิน หรือ 1 เมษายนสำหรับปีการศึกษา ไม่ใช่การกรอกรายละเอียดบทความตีพิมพ์
- การกด - ลดรายการล่าสุดในปีและประเภทที่เลือกของอาจารย์คนนั้น หากมีผู้เขียนร่วมคนอื่น ระบบจะเก็บผลงานและผู้เขียนคนอื่นไว้
- ปุ่มแก้ไขเปิดฟอร์มชื่อผลงาน วันที่ตีพิมพ์ ประเภท วารสาร และหมวดหมู่ กดบันทึกเพื่ออัปเดตฐานข้อมูลและคำนวณสรุปใหม่ ไม่เปลี่ยนรายชื่อหรือบทบาทผู้เขียน ตรวจ revision ก่อนอัปเดตเพื่อป้องกันการเขียนทับรายการที่เปลี่ยนไปแล้ว
- รายชื่อเรียงตามตำแหน่งวิชาการเท่านั้น: ศ. → รศ. → ผศ. → อาจารย์/คำนำหน้าอื่น รองรับทั้งชื่อย่อและชื่อเต็ม ตำแหน่งเท่ากันเรียงตามชื่อ นามสกุล และรหัส ตำแหน่งบริหารหรือสิทธิ์ระบบไม่ส่งผลต่อลำดับ
- Frontend แสดงผลจากคำตอบที่บันทึกสำเร็จ ปิดปุ่มระหว่างบันทึก และให้โหลดใหม่หลังข้อผิดพลาดเพื่อป้องกันการส่งซ้ำโดยไม่ทราบผล
- สิทธิ์เดิม: อาจารย์ตำแหน่งงานวิจัย 9 หรือ `RESEARCH_RECORD_MANAGE` แก้ไขได้; คณบดีตำแหน่ง 1 อ่านอย่างเดียว; `RESEARCH_SUMMARY_VIEW` อ่านได้ ตรวจจากฐานข้อมูลทุกคำขอ
- ไม่เพิ่มตารางหรือ migration ใช้คอลัมน์เดิมใน `faculty_research` รวมถึง author IDs และ JSON `co_author_ids` ไม่ส่ง file path หรือข้อมูลส่วนตัวอาจารย์นอกเหนือชื่อและรหัสไปยังหน้าสรุป

## การตรวจสอบ

`backend/tests/research-summary-smoke.php` ทดสอบ HTTP API ด้วยฐานข้อมูลชื่อ `test_research_<12 hex>` ที่สร้างแยกและข้อมูลสมมติเท่านั้น แล้วลบทิ้งหลังจบ ครอบคลุมสิทธิ์ การเพิ่มทุกประเภท การโหลดซ้ำ การลบ ผู้เขียนร่วม ข้อมูลผิด และ rollback เมื่อ audit ล้มเหลว ต้องใช้ PHP ที่มี PDO MySQL และสิทธิ์สร้าง/ลบเฉพาะฐานข้อมูลทดสอบ หรือกำหนด `RESEARCH_TEST_DATABASE` ให้ตรงกับฐานข้อมูลทดสอบที่ได้รับสิทธิ์ไว้ (ต้องยังไม่มีฐานข้อมูลชื่อนั้น)

ไม่พบไฟล์ `MYSQL_DATABASE.sql` หรือ `MYSQL_DATABASE (3-8-2569).sql` ใน checkout นี้ จึงเทียบชื่อคอลัมน์และชนิดข้อมูลกับ schema ของ MySQL ใน Docker โดยไม่อ่านแถวข้อมูลส่วนบุคคล ไม่มีการเปลี่ยน schema หรือ import ข้อมูลจริง
