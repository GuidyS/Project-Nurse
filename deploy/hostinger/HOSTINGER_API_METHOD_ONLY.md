# วิธีปรับ API ของ Nurse MIS ให้ใช้บน Hostinger

เอกสารนี้มีเฉพาะขั้นตอนสำหรับนำระบบที่พัฒนาใน Docker ไปใช้บน Hostinger ไม่มีโค้ดและไม่มีข้อมูลเข้าสู่ระบบจริง

## 1. ตรวจสภาพแวดล้อมบน Hostinger

1. ให้เว็บไซต์ใช้ PHP 8.2 ขึ้นไป และเปิดส่วนขยายที่ระบบต้องใช้ โดยเฉพาะ PDO MySQL
2. เปิด HTTPS ให้โดเมน
3. ยืนยันว่าไฟล์หน้าเว็บอยู่ใน `public_html/` และ PHP API อยู่ใน `public_html/api/`
4. ตรวจชื่อฐานข้อมูล ผู้ใช้ฐานข้อมูล และ MySQL host จาก hPanel ของบัญชีนั้น อย่าสมมติว่า host เป็น `db` เหมือนใน Docker

## 2. ตั้งค่าการเชื่อมต่อฐานข้อมูล

1. สร้างไฟล์ `public_html/api/config/config.local.php` **บน Hostinger** จากไฟล์ตัวอย่าง `deploy/hostinger/config.local.example.php`
2. กรอก host, port, ชื่อฐานข้อมูล, ผู้ใช้ และรหัสผ่านที่ได้จาก hPanel
3. อย่านำไฟล์ที่มีค่าจริงใส่ ZIP, Git, Markdown หรือแชต
4. ให้ API ใช้ตัวเชื่อมต่อกลางใน `api/config/config.php` แทนการกำหนด `host=db` และชื่อผู้ใช้ของ Docker ไว้ในแต่ละ endpoint

## 3. ให้หน้าเว็บเรียก API บนโดเมนเดียวกัน

1. ตอน build frontend สำหรับ production ตั้งค่า API base URL เป็น `/api`
2. อัปโหลดไฟล์ frontend ที่ build แล้วไป `public_html/`
3. ตรวจผ่าน Network ของเบราว์เซอร์ว่า request ไปที่ `https://<โดเมน>/api/index.php?page=...` ไม่ใช่ `localhost:8080`

## 4. ปรับ endpoint ที่ยังใช้ค่า Docker

1. ค้นหาใน backend ว่ามี endpoint ใดเปิดฐานข้อมูลด้วย `mysql:host=db` โดยตรง
2. เปลี่ยน endpoint เหล่านั้นให้ใช้ตัวเชื่อมต่อกลางของระบบ
3. ตรวจ endpoint ทั้งส่วนอ่านและส่วนบันทึกของแต่ละหน้า อย่าตรวจแค่ตอนเปิดหน้า เช่น การแจ้งเตือน, CLO Map, CLO รายวิชา และคลังเอกสาร
4. ตรวจ SQL prepared statement ว่าชื่อ parameter แต่ละตำแหน่งไม่ซ้ำกัน เมื่อปิด PDO emulated prepares
5. ตรวจว่าลิงก์เอกสารและไฟล์ดาวน์โหลดที่ API ส่งกลับไม่มี `localhost` และชี้ไปยังโดเมน production

## 5. รักษา session และสิทธิ์

1. ให้ endpoint ตรวจ session ที่ backend ก่อนอ่านหรือแก้ข้อมูล
2. ให้ endpoint ที่เกี่ยวข้องกับเอกสารหรือข้อมูลอ่อนไหวตรวจ role และขอบเขตข้อมูลก่อนส่งผลลัพธ์
3. ให้การดาวน์โหลดไฟล์ตรวจ path ว่ายังอยู่ใต้โฟลเดอร์ `api/uploads/` ที่อนุญาต
4. ตั้งค่า Apache ให้เรียก PHP ผ่าน `api/index.php` และปิดการเข้าถึง `api/config/` กับ `api/components/` โดยตรง

## 6. อัปโหลดและตรวจผล

1. สำรองไฟล์เว็บและฐานข้อมูลก่อนเปลี่ยนระบบจริง เก็บไฟล์สำรองไว้นอก `public_html/`
2. อัปโหลดเฉพาะไฟล์ที่ตรวจแล้วไปยังตำแหน่งเดิมบน Hostinger และตรวจว่าไม่ได้สร้าง `public_html/public_html/` ซ้อนกัน
3. ตรวจว่า `config.local.php` ที่มีค่าจริงยังอยู่หลังอัปเดต และย้าย ZIP ชั่วคราวออกจากพื้นที่เว็บ
4. ทดสอบการล็อกอินและเปิดหน้าที่ได้รับผลกระทบด้วยบัญชีทดสอบตามบทบาท
5. ทดสอบ API โดยไม่ล็อกอิน: endpoint ที่ต้องใช้ session ควรตอบ `401`; ไฟล์ config และ component ที่เรียกตรงควรถูกปฏิเสธ
6. แยกผล `200` พร้อมรายการว่างออกจาก `500`: รายการว่างอาจเป็นผลจากสิทธิ์ การมอบหมาย หรือข้อมูลยังไม่มี ส่วน `500` ต้องตรวจ PHP error log และการเชื่อมต่อฐานข้อมูล
7. ทดสอบปุ่มบันทึก อัปโหลด ดาวน์โหลด และลบด้วยข้อมูลทดสอบที่ได้รับอนุญาตก่อนใช้งานจริง

## สถานะของชุดแก้ที่จัดเตรียมไว้

ไฟล์ที่แก้และทดสอบแล้วครอบคลุมการอ่านข้อมูลของหน้าแจ้งเตือน, CLO Map, CLO รายวิชา และคลังเอกสาร รวมถึงการดาวน์โหลดเอกสารบางส่วน ยังมี endpoint เก่าสำหรับบันทึก CLO Map และอัปโหลด/ลบเอกสารที่ใช้ค่าฐานข้อมูล Docker จึงต้องตรวจและแก้ต่อก่อนถือว่าทุกปุ่มพร้อมใช้งานบน Hostinger ไม่มีการเพิ่มหรือทดสอบ flow grade/score ตามขอบเขตล่าสุดของโครงการ
