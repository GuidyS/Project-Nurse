## 1. ระบบส่งอีเมลตอนไหนบ้าง

ตอนนี้มี 2 เรื่อง

| เรื่อง | ส่งเมื่อไหร่ | ส่งถึงใคร |
| --- | --- | --- |
| ใบประกอบวิชาชีพใกล้หมดอายุ | เหลือ 6 เดือน / 3 เดือน / 1 เดือน ก่อนวันหมดอายุ | อีเมลในข้อมูลส่วนตัวของอาจารย์เจ้าของใบอนุญาต |
| โครงการใกล้สิ้นสุด | เหลือ 30 วัน / 14 วัน ก่อนวันสิ้นสุด (ไม่รวมโครงการที่เสร็จสิ้นหรือยกเลิกแล้ว) | อีเมลคณะ ตามค่า `PROJECT_REMINDER_EMAIL` |

**สำคัญ:** ถ้ายังไม่ตั้งค่า SMTP ระบบ **ไม่พัง** — การแจ้งเตือนในหน้า "การแจ้งเตือน" ยังขึ้นตามปกติทุกอย่าง
แค่ไม่มีอีเมลส่งออกไปเท่านั้น (ระบบจะบันทึกสถานะไว้ว่า `not_configured`)

### งานเบื้องหลังทำงานยังไง

ระบบนี้ไม่ได้ใช้ cron แต่ใช้วิธี "ตรวจเมื่อมีคนเปิดใช้งาน" แทน คือทุกครั้งที่หน้าเว็บเรียก API การแจ้งเตือน
(แถบด้านข้างเรียกทุก 30 วินาที) ระบบจะเช็กว่าถึงรอบทำงานหรือยัง ถ้าเกิน 60 นาทีจากรอบที่แล้วจึงจะทำงานอีกครั้ง
และมีการล็อกกันไม่ให้ทำงานซ้อนกันเวลาหลายคนเปิดพร้อมกัน

แปลว่า **ต้องมีคนล็อกอินใช้งานระบบอย่างน้อยวันละครั้ง** อีเมลถึงจะถูกส่ง

## 2. ไฟล์ .env กับ .env.example ต่างกันยังไง

| ไฟล์ | ขึ้น git ไหม | เนื้อหา | ใครสร้าง |
| --- | --- | --- | --- |
| `.env.example` | **ขึ้น** (ทุกคนเห็น) | ชื่อตัวแปร + คำอธิบาย ค่าว่างเปล่า ไม่มีรหัสผ่าน | มีอยู่ใน repo แล้ว |
| `.env` | **ไม่ขึ้น** (อยู่ใน `.gitignore`) | ค่าจริง รวมรหัสผ่าน | แต่ละคนสร้างเองในเครื่องตัวเอง |

`.env.example` คือ *แม่แบบ* ห้ามใส่รหัสผ่านจริงลงไป เพราะมันขึ้น git
ส่วน `.env` คือไฟล์ที่ Docker เอาไปใช้จริง **ห้าม commit เด็ดขาด**

### ทำไมต้องวางไว้ข้าง docker-compose.yml

Docker Compose จะมองหาไฟล์ชื่อ `.env` ที่อยู่ **โฟลเดอร์เดียวกับ `docker-compose.yml`** โดยอัตโนมัติ
แล้วแทนค่าให้ตัวแปร `${SMTP_HOST}` ฯลฯ ที่เขียนไว้ใน `docker-compose.yml`
ถ้าวางไว้ที่อื่น (เช่นนอกโปรเจกต์ หรือในโฟลเดอร์ `backend/`) Docker จะหาไม่เจอ และค่าทุกตัวจะว่างเปล่า

```
Project-Nurse-main/
├── .env              ← สร้างไฟล์นี้ (ไม่ขึ้น git)
├── .env.example      ← แม่แบบ มีอยู่แล้ว
├── docker-compose.yml
├── backend/
└── frontend/
```

> **หมายเหตุ:** `frontend/.env` เป็นคนละไฟล์กัน ใช้เก็บ `VITE_API_BASE_URL` ของฝั่งหน้าเว็บ
> ไม่เกี่ยวกับอีเมล และไม่ต้องไปแก้

## 3. ขั้นตอนตั้งค่า (ทำครั้งเดียวต่อเครื่อง)

### ขั้นที่ 1 — สร้างไฟล์ .env

เปิด terminal ที่โฟลเดอร์โปรเจกต์ (โฟลเดอร์ที่มี `docker-compose.yml`)

```bash
cp .env.example .env
```

ถ้าใช้ Windows PowerShell

```powershell
Copy-Item .env.example .env
```

หรือจะก๊อปวางด้วยมือใน File Explorer แล้วเปลี่ยนชื่อก็ได้ (ระวัง Windows ซ่อนนามสกุลไฟล์
ต้องให้ชื่อเป็น `.env` เฉย ๆ ไม่ใช่ `.env.txt`)

### ขั้นที่ 2 — กรอกค่าจริง

เปิด `.env` ด้วย VS Code หรือ Notepad แล้วกรอกตามหัวข้อ [4](#4-แบบที่-1--gmail-ส่วนตัว-แนะนำสำหรับทดสอบ) หรือ [5](#5-แบบที่-2--อีเมลคณะ-siamedu-สำหรับใช้งานจริง)

### ขั้นที่ 3 — รีสตาร์ท container backend

ค่าใน `.env` จะถูกอ่านตอน container **เริ่มทำงาน** เท่านั้น แก้ไฟล์แล้วต้องรีสตาร์ทเสมอ

```bash
docker compose up -d backend
```

### ขั้นที่ 4 — ตรวจว่าค่าเข้าไปจริง

```bash
docker compose exec backend printenv SMTP_HOST SMTP_PORT SMTP_USERNAME SMTP_FROM_EMAIL
```

ถ้าขึ้นค่าที่กรอกไว้ครบ = ใช้ได้ ถ้าว่างเปล่า แปลว่าไฟล์ `.env` วางผิดที่หรือชื่อไฟล์ผิด

## 4. แบบที่ 1 — Gmail ส่วนตัว (แนะนำสำหรับทดสอบ)

Gmail **ไม่ยอมให้ใช้รหัสผ่านปกติ** ส่งอีเมลผ่าน SMTP แล้ว ต้องสร้าง "App password" แทน

### 4.1 เปิด 2-Step Verification ก่อน

App password จะสร้างไม่ได้เลยถ้ายังไม่เปิด 2-Step Verification

1. เข้า https://myaccount.google.com/security
2. หาหัวข้อ **How you sign in to Google** → **2-Step Verification**
3. กดเปิด แล้วทำตามขั้นตอน (ยืนยันด้วยเบอร์โทรหรือแอป Google)

### 4.2 สร้าง App password

1. เข้า https://myaccount.google.com/apppasswords
   (ถ้าเข้าไม่ได้ / ไม่เจอเมนู แปลว่ายังเปิด 2-Step Verification ไม่สำเร็จ)
2. ตั้งชื่อให้จำได้ เช่น `Nursing MIS`
3. กด **Create**
4. Google จะโชว์รหัส **16 ตัวอักษร** เช่น `abcd efgh ijkl mnop`
   → **ก๊อปเก็บไว้ทันที ปิดหน้าต่างแล้วดูซ้ำไม่ได้**

### 4.3 กรอกลง .env

เอาช่องว่างในรหัส 16 ตัวออกให้หมด แล้วกรอกแบบนี้

```dotenv
SMTP_HOST=smtp.gmail.com
SMTP_PORT=587
SMTP_SECURE=tls
SMTP_USERNAME=ชื่อบัญชีของคุณ@gmail.com
SMTP_PASSWORD=abcdefghijklmnop
SMTP_FROM_EMAIL=ชื่อบัญชีของคุณ@gmail.com
SMTP_FROM_NAME=ระบบบริหารจัดการคณะพยาบาลศาสตร์

APP_URL=http://localhost:5173
PROJECT_REMINDER_EMAIL=อีเมลที่อยากให้รับแจ้งเตือนโครงการ@gmail.com
```

**ข้อควรรู้เรื่อง Gmail**

- `SMTP_FROM_EMAIL` ต้องเป็นอีเมลเดียวกับ `SMTP_USERNAME` ถ้าใส่คนละอันอีเมลจะถูกส่งในนาม `SMTP_USERNAME` อยู่ดี
- Gmail ฟรีจำกัดการส่งประมาณ 500 ฉบับ/วัน เพียงพอสำหรับการทดสอบ
- ตอนทดสอบ ให้ลองใส่ `PROJECT_REMINDER_EMAIL` เป็นอีเมลตัวเองจะได้เห็นผลทันที

## 5. แบบที่ 2 — อีเมลคณะ @siam.edu (สำหรับใช้งานจริง)

อีเมลของมหาวิทยาลัยสยามใช้ระบบ **Microsoft 365** ค่าที่ใช้จึงเป็นของ Outlook/Office 365

### 5.1 ค่าที่ต้องกรอก

```dotenv
SMTP_HOST=smtp.office365.com
SMTP_PORT=587
SMTP_SECURE=tls
SMTP_USERNAME=บัญชีคณะ@siam.edu
SMTP_PASSWORD=รหัสผ่านหรือ App password ของบัญชีนั้น
SMTP_FROM_EMAIL=บัญชีคณะ@siam.edu
SMTP_FROM_NAME=คณะพยาบาลศาสตร์ มหาวิทยาลัยสยาม

APP_URL=http://localhost:5173
PROJECT_REMINDER_EMAIL=nus1@siam.edu
```

`PROJECT_REMINDER_EMAIL=nus1@siam.edu` เป็นค่าเริ่มต้นของระบบอยู่แล้ว ถ้าไม่กรอกก็ใช้ค่านี้

### 5.2 สิ่งที่ต้องขอจากผู้ดูแลระบบของมหาวิทยาลัย

Microsoft 365 ปิดการส่ง SMTP ไว้เป็นค่าเริ่มต้น ต้องให้ผู้ดูแลเปิดให้ก่อน มิฉะนั้นจะส่งไม่ผ่านแน่นอน
ให้แจ้งผู้ดูแลตามนี้

1. **เปิด SMTP AUTH ให้บัญชีที่จะใช้ส่ง**
   ผู้ดูแลเข้า Microsoft 365 admin center → Users → เลือกบัญชี → Mail → Manage email apps
   → ติ๊ก **Authenticated SMTP**
2. **ถ้าบัญชีเปิด MFA (ยืนยันตัวตน 2 ชั้น)** ต้องสร้าง **App password** ให้ ใช้รหัสผ่านปกติไม่ได้
3. **ถ้าองค์กรปิด App password ทั้งระบบ** ให้ขอทางเลือกอื่นแทน เช่น
   - ขอ **บัญชีเฉพาะสำหรับระบบ** (service account) ที่ไม่เปิด MFA และเปิด SMTP AUTH ให้
   - หรือขอใช้ **SMTP relay ภายในของมหาวิทยาลัย** ซึ่งมักไม่ต้องใส่รหัสผ่าน ถ้าเป็นกรณีนี้ให้กรอกแบบนี้แทน

     ```dotenv
     SMTP_HOST=ที่อยู่ relay ที่ผู้ดูแลให้มา
     SMTP_PORT=25
     SMTP_SECURE=none
     SMTP_USERNAME=
     SMTP_PASSWORD=
     SMTP_FROM_EMAIL=nus1@siam.edu
     SMTP_FROM_NAME=คณะพยาบาลศาสตร์ มหาวิทยาลัยสยาม
     ```

     ระบบรองรับกรณีไม่ใส่ username/password อยู่แล้ว (จะไม่พยายามล็อกอิน)
     แต่ `SMTP_SECURE=none` **ใช้ได้เฉพาะกับ relay ภายในองค์กรเท่านั้น** ห้ามใช้กับเซิร์ฟเวอร์ภายนอก

### 5.3 เรื่องที่ควรคุยกับผู้ดูแลเพิ่ม

- ถ้าจะให้อีเมลไม่ตกโฟลเดอร์สแปม ควรขอให้เพิ่มระเบียน **SPF/DKIM** ให้เรียบร้อย
- ถ้า deploy ขึ้นเซิร์ฟเวอร์จริง อย่าลืมเปลี่ยน `APP_URL` เป็น URL จริงของระบบ
  เพราะค่านี้คือลิงก์ "เข้าสู่ระบบ" ที่อยู่ในเนื้ออีเมล ถ้ายังเป็น `localhost` ผู้รับจะกดแล้วเปิดไม่ได้

## 6. ความหมายของค่าทุกตัวใน .env

| ตัวแปร | จำเป็น | ค่าเริ่มต้น | อธิบาย |
| --- | --- | --- | --- |
| `SMTP_HOST` | ใช่ | (ว่าง) | ที่อยู่เซิร์ฟเวอร์ส่งอีเมล **ถ้าว่าง = ปิดการส่งอีเมลทั้งระบบ** |
| `SMTP_PORT` | ไม่ | `587` | พอร์ต ใช้ `587` คู่กับ tls, `465` คู่กับ ssl, `25` คู่กับ none |
| `SMTP_SECURE` | ไม่ | `tls` | `tls` = STARTTLS, `ssl` = เข้ารหัสตั้งแต่เชื่อมต่อ, `none` = ไม่เข้ารหัส (ทดสอบ/relay ภายในเท่านั้น) |
| `SMTP_USERNAME` | แล้วแต่ | (ว่าง) | บัญชีที่ใช้ล็อกอิน ถ้าเว้นว่างระบบจะไม่ล็อกอิน (ใช้กับ relay ที่ไม่ต้องยืนยันตัวตน) |
| `SMTP_PASSWORD` | แล้วแต่ | (ว่าง) | รหัสผ่านหรือ App password คู่กับ `SMTP_USERNAME` |
| `SMTP_FROM_EMAIL` | ใช่ | ใช้ `SMTP_USERNAME` | อีเมลผู้ส่งที่แสดงให้ผู้รับเห็น **ถ้าทั้งตัวนี้และ USERNAME ว่าง = ปิดการส่ง** |
| `SMTP_FROM_NAME` | ไม่ | `ระบบบริหารจัดการคณะพยาบาลศาสตร์` | ชื่อผู้ส่งที่แสดงให้ผู้รับเห็น |
| `APP_URL` | ไม่ | `http://localhost:5173` | ลิงก์ "เข้าสู่ระบบ" ที่อยู่ในเนื้ออีเมล |
| `PROJECT_REMINDER_EMAIL` | ไม่ | `nus1@siam.edu` | อีเมลที่รับแจ้งเตือนโครงการใกล้สิ้นสุด |

**กฎที่ควรจำ**

- ระบบจะถือว่า "ตั้งค่าแล้ว" ก็ต่อเมื่อ `SMTP_HOST` **และ** `SMTP_FROM_EMAIL` (หรือ `SMTP_USERNAME`) มีค่าทั้งคู่
- ค่าใน `.env` **ไม่ต้องใส่เครื่องหมายคำพูด** เขียน `SMTP_HOST=smtp.gmail.com` ตรง ๆ ได้เลย
- ห้ามเว้นวรรครอบเครื่องหมาย `=` เช่น `SMTP_HOST = smtp.gmail.com` จะอ่านค่าผิด

## 7. วิธีทดสอบว่าส่งได้จริง

### 7.1 เช็กว่า container เห็นค่าหรือยัง

```bash
docker compose exec backend printenv SMTP_HOST SMTP_FROM_EMAIL
```

### 7.2 ยิงทดสอบส่งจริง 1 ฉบับ

```bash
docker compose exec backend php -r "require '/var/www/html/config/mailer.php'; var_dump(appSendMail('อีเมลผู้รับที่ใช้ทดสอบ','ผู้ทดสอบ','ทดสอบระบบแจ้งเตือน','<p>ทดสอบส่งอีเมลจาก Nursing MIS</p>','ทดสอบส่งอีเมลจาก Nursing MIS'));"
```

ผลลัพธ์ที่เป็นไปได้

| ผลลัพธ์ | แปลว่า |
| --- | --- |
| `status => "sent"` | สำเร็จ ไปเช็กกล่องจดหมายได้เลย (ดูโฟลเดอร์ Junk/Spam ด้วย) |
| `status => "not_configured"` | ยังไม่ได้ตั้ง `SMTP_HOST` หรือ `SMTP_FROM_EMAIL` / ลืมรีสตาร์ท container |
| `status => "invalid_recipient"` | รูปแบบอีเมลผู้รับไม่ถูกต้อง |
| `status => "failed"` | เชื่อมต่อหรือล็อกอินไม่ผ่าน ดูข้อความใน `error` แล้วไปหัวข้อถัดไป |

### 7.3 ดูสถานะการส่งของการแจ้งเตือนจริง

ระบบเก็บผลการส่งไว้ในตาราง ดูย้อนหลังได้

```sql
SELECT faculty_id, stage_months, email_to, email_status, email_error, email_sent_at
FROM faculty_license_reminders
ORDER BY id DESC LIMIT 20;
```

ความหมายของ `email_status`

| ค่า | แปลว่า |
| --- | --- |
| `sent` | ส่งสำเร็จ |
| `failed` | ส่งไม่สำเร็จ ดูรายละเอียดที่ `email_error` (ระบบจะลองใหม่ได้สูงสุด 5 ครั้ง) |
| `no_email` | อาจารย์คนนั้นยังไม่มีอีเมลในข้อมูลส่วนตัว |
| `disabled` | ผู้ใช้ปิดรับแจ้งเตือนทางอีเมลเอง |
| `not_configured` | ระบบยังไม่ได้ตั้งค่า SMTP |

## 8. ปัญหาที่เจอบ่อยและวิธีแก้

| อาการ / ข้อความผิดพลาด | สาเหตุ | วิธีแก้ |
| --- | --- | --- |
| `not_configured` ทั้งที่กรอก `.env` แล้ว | ลืมรีสตาร์ท container | `docker compose up -d backend` |
| `printenv` ไม่ขึ้นค่าอะไรเลย | ไฟล์ `.env` วางผิดที่ หรือชื่อเป็น `.env.txt` | ย้ายไปไว้ข้าง `docker-compose.yml` และแก้ชื่อให้ถูก |
| `Username and Password not accepted` (Gmail) | ใช้รหัสผ่าน Gmail ปกติ | ต้องใช้ App password 16 ตัว |
| `SMTP AUTH extension not supported` / `5.7.139` (Office 365) | บัญชียังไม่ได้เปิด Authenticated SMTP | ให้ผู้ดูแลเปิดให้ตามหัวข้อ 5.2 |
| `Connection timed out` / `SMTP connect() failed` | พอร์ตถูกไฟร์วอลล์หรือเครือข่ายบล็อก | ลองเปลี่ยน `SMTP_PORT=465` + `SMTP_SECURE=ssl` หรือทดสอบจากเครือข่ายอื่น |
| `Could not authenticate` แต่รหัสถูก | ใส่รหัสมีช่องว่างติดมา | ลบช่องว่างทั้งหมดออกจาก `SMTP_PASSWORD` |
| ส่งได้แต่เข้า Spam | ยังไม่ได้ตั้ง SPF/DKIM | ขอผู้ดูแลระบบเพิ่มระเบียนให้ (ตอนทดสอบกด "Not spam" ไปก่อนได้) |
| อีเมลไม่ออกสักที ทั้งที่ตั้งค่าถูก | ไม่มีคนใช้งานระบบ งานเบื้องหลังจึงไม่ถูกกระตุ้น หรือยังไม่ถึงรอบ 60 นาที | ล็อกอินเข้าระบบ รอสักครู่ แล้วเช็กตารางตามหัวข้อ 7.3 |
| ลิงก์ในอีเมลกดแล้วเปิดไม่ได้ | `APP_URL` ยังเป็น `localhost` | เปลี่ยนเป็น URL จริงของเซิร์ฟเวอร์ |

## 9. ข้อควรระวังด้านความปลอดภัย

- **ห้าม commit ไฟล์ `.env` ขึ้น git** ถึงจะอยู่ใน `.gitignore` แล้วก็ควรเช็ก `git status` ก่อน commit ทุกครั้ง
- **ห้ามใส่รหัสผ่านจริงลงใน `.env.example`** เพราะไฟล์นั้นขึ้น git และทุกคนเห็น
- **ห้ามส่งรหัสผ่านผ่านแชทกลุ่มหรือ LINE** ถ้าต้องส่งต่อให้ใช้ช่องทางที่ปลอดภัยกว่า
- ควรใช้ **App password แยกต่อคนต่อเครื่อง** ไม่ใช้ร่วมกัน เพราะเวลาต้องยกเลิกจะได้ยกเลิกเฉพาะตัวที่มีปัญหา
- ถ้าเผลอเปิดเผยรหัสผ่านออกไป ให้เข้าไป **ลบ App password ตัวนั้นทิ้งทันที** แล้วสร้างใหม่
  (Gmail: https://myaccount.google.com/apppasswords)
- บนเครื่องใช้งานจริง ควรใช้บัญชีของคณะ ไม่ใช่ Gmail ส่วนตัวของใครคนใดคนหนึ่ง
  เพราะถ้าคนนั้นเปลี่ยนรหัสหรือลาออก ระบบจะหยุดส่งอีเมลทันที
